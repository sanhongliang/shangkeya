# 上课鸭 云架构升级方案

> 目标：课件保持本地磁盘；学员/课程/课表等业务数据上云（服务器 PostgreSQL）；
> 桌面端（Tauri）改为读写服务器数据；教师端通过公网网页（手机浏览器）查看/编辑课表。
> 状态：待确认（2026-10-16）

## 一、总体架构

```
┌─────────────────────────────┐        ┌──────────────────────────────┐
│  桌面端 上课鸭 (Tauri)        │        │  云服务器                     │
│  ├ 课件：本地磁盘直读(不变)    │  HTTPS │  ├ Nginx 反向代理(SSL)         │
│  ├ 业务数据：HTTP API 读写    │◄──────►│  ├ Node.js API 服务           │
│  │   (登录/学员/课程/课表/… )  │        │  ├ 静态网页(手机端课表)        │
│  └ localStorage: 仅登录缓存   │        │  └ PostgreSQL 数据库          │
└─────────────────────────────┘        └──────────────────────────────┘
                                              ▲
                                              │ HTTPS
┌─────────────────────────────┐              │
│  教师手机（浏览器）            │──────────────┘
│  课表查看 / 编辑 / 学员课程    │
└─────────────────────────────┘
```

- **课件**：留在本地（TIFF/PDF/图片直读，不迁移、不传云）——现状不变。
- **业务数据**：学员、课程、课表、充值、成绩、公告、账号 → 服务器 PostgreSQL。
- **桌面端**：数据层改为 HTTP API（保留登录态本地缓存；课件加载仍走本地文件）。
- **手机端**：公网静态网页 + API，响应式适配手机屏幕，只开放课表相关能力。

## 二、技术选型（建议）

| 层 | 选型 | 理由 |
|---|---|---|
| 数据库 | PostgreSQL | 用户已选；云服务器标配 |
| 后端 | Node.js + Express + pg | 与前端同为 TypeScript/JS，生态成熟，部署简单 |
| 认证 | JWT（Access + Refresh） | 桌面端/手机端共用 |
| 反代/HTTPS | Nginx + Let's Encrypt | 公网访问必需 |
| 前端(手机页) | 复用现有 React 工程做移动端适配 | 课表组件复用，一套代码两处用 |

## 三、数据库设计（PostgreSQL）

库：`shangkeya`。全部业务表含 `created_at / updated_at`；机构维度（多个教师账号共用同一套学员课程时）预留 `org_id`。

### 3.1 账号与认证
```sql
CREATE TABLE accounts (
  id            BIGSERIAL PRIMARY KEY,
  org_id        BIGINT DEFAULT 1,          -- 预留多机构
  username      TEXT NOT NULL UNIQUE,      -- 登录名
  password_hash TEXT NOT NULL,             -- bcrypt
  name          TEXT,                      -- 教师姓名
  role          TEXT DEFAULT 'teacher',    -- teacher/admin
  active        BOOLEAN DEFAULT true,
  created_at    TIMESTAMPTZ DEFAULT now(),
  updated_at    TIMESTAMPTZ DEFAULT now()
);
```

### 3.2 学员
```sql
CREATE TABLE students (
  id            BIGSERIAL PRIMARY KEY,
  org_id        BIGINT DEFAULT 1,
  name          TEXT NOT NULL,
  phone         TEXT,
  grade         TEXT,            -- 年级
  school        TEXT,            -- 学校
  parent_phone  TEXT,            -- 家长电话
  notes         TEXT,            -- 备注
  balance       NUMERIC(12,2) DEFAULT 0,  -- 剩余课时/余额
  active        BOOLEAN DEFAULT true,
  created_at    TIMESTAMPTZ DEFAULT now(),
  updated_at    TIMESTAMPTZ DEFAULT now()
);
```

### 3.3 课程
```sql
CREATE TABLE courses (
  id            BIGSERIAL PRIMARY KEY,
  org_id        BIGINT DEFAULT 1,
  name          TEXT NOT NULL,
  subject       TEXT,            -- 科目
  grade         TEXT,            -- 适用年级
  duration_min  INTEGER DEFAULT 60,
  price         NUMERIC(12,2),   -- 单价
  notes         TEXT,
  active        BOOLEAN DEFAULT true,
  created_at    TIMESTAMPTZ DEFAULT now(),
  updated_at    TIMESTAMPTZ DEFAULT now()
);
```

### 3.4 课表（核心，手机端主要操作对象）
```sql
CREATE TABLE schedule (
  id            BIGSERIAL PRIMARY KEY,
  org_id        BIGINT DEFAULT 1,
  student_id    BIGINT NOT NULL REFERENCES students(id) ON DELETE CASCADE,
  course_id     BIGINT NOT NULL REFERENCES courses(id) ON DELETE CASCADE,
  start_at      TIMESTAMPTZ NOT NULL,     -- 上课开始时间（含日期）
  end_at        TIMESTAMPTZ NOT NULL,     -- 结束时间
  teacher_id    BIGINT REFERENCES accounts(id),
  status        TEXT DEFAULT 'scheduled', -- scheduled/done/canceled/absent
  notes         TEXT,
  created_at    TIMESTAMPTZ DEFAULT now(),
  updated_at    TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_schedule_start ON schedule(org_id, start_at);
CREATE INDEX idx_schedule_student ON schedule(org_id, student_id);
```

### 3.5 充值 / 成绩 / 公告 / 设置
```sql
CREATE TABLE recharges (
  id            BIGSERIAL PRIMARY KEY,
  org_id        BIGINT DEFAULT 1,
  student_id    BIGINT NOT NULL REFERENCES students(id) ON DELETE CASCADE,
  amount        NUMERIC(12,2) NOT NULL,
  type          TEXT DEFAULT 'recharge',  -- recharge/consume/refund
  note          TEXT,
  created_at    TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE scores (
  id            BIGSERIAL PRIMARY KEY,
  org_id        BIGINT DEFAULT 1,
  student_id    BIGINT NOT NULL REFERENCES students(id) ON DELETE CASCADE,
  exam_name     TEXT,
  subject       TEXT,
  score         NUMERIC(8,2),
  total         NUMERIC(8,2),
  note          TEXT,
  created_at    TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE announcements (
  id            BIGSERIAL PRIMARY KEY,
  org_id        BIGINT DEFAULT 1,
  title         TEXT NOT NULL,
  content       TEXT,
  active        BOOLEAN DEFAULT true,
  created_at    TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE settings (
  org_id        BIGINT PRIMARY KEY DEFAULT 1,
  payload       JSONB NOT NULL DEFAULT '{}'  -- 黑板样式/画面比例/隐藏题目等设置
);
```
> 说明：桌面端现有 `localStorage:shangkeya:app` 中的业务数据字段全部映射到上述表；
> 表结构可按现有前端字段精调（迁移阶段逐字段对齐）。

## 四、API 设计（REST，前缀 `/api`）

认证：`Authorization: Bearer <jwt>`（桌面端/手机端共用）。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/auth/login | 登录（返回 JWT + 用户信息） |
| POST | /api/auth/refresh | 刷新令牌 |
| GET  | /api/students | 学员列表（支持 name/grade 搜索） |
| POST | /api/students | 新增学员 |
| PUT  | /api/students/:id | 编辑学员 |
| DELETE | /api/students/:id | 删除学员 |
| GET  | /api/courses | 课程列表 |
| POST | /api/courses | 新增课程 |
| PUT  | /api/courses/:id | 编辑课程 |
| DELETE | /api/courses/:id | 删除课程 |
| GET  | /api/schedule?from=&to=&student_id= | 课表查询（按日期范围/学员过滤）——手机端 |
| POST | /api/schedule | 新增课次（手机端/桌面端） |
| PUT  | /api/schedule/:id | 编辑课次（改时间/状态/学员课程）——手机端 |
| DELETE | /api/schedule/:id | 删除课次 |
| GET  | /api/recharges?student_id= | 充值/扣费记录 |
| POST | /api/recharges | 新增充值/扣费 |
| GET  | /api/scores?student_id= | 成绩列表 |
| POST | /api/scores | 新增成绩 |
| GET  | /api/announcements | 公告 |
| GET/PUT | /api/settings | 机构设置（JSONB 读写） |

错误格式统一：`{ error: { code, message } }`。

## 五、桌面端改造（Tauri 前端）

1. **数据层抽象**：新建 `src/api/` 模块（fetch 封装 + JWT 存储），
   `src/data/` 中原 localStorage 读写替换为 API 调用：
   - StudentsPage / SchedulePage / SalaryPage / CoursewarePage(仅列表) / SettingsPage / Announcement
   - 登录页：改为 API 登录（本地不再校验 accounts）
2. **本地保留**：
   - 登录缓存（localStorage `shangkeya:auth`，存 JWT，失效走 refresh）
   - 课件相关（IndexedDB 文件、导入缓存、本地磁盘直读）——不变
   - `courseware` 目录列表仍可本地维护（课件不上云）
3. **API 地址配置**：`src/config.ts`（默认指向服务器域名，开发期可指向本地后端）。

## 六、手机端网页（教师端课表）

- **形式**：现有 React 工程新增移动端路由（`/m/schedule` 等），构建后静态部署到服务器，Nginx 直接伺服 + 反代 `/api`。
- **页面**：
  1. 登录页（手机号/账号 + 密码 → JWT）
  2. 课表页（日/周视图；默认显示本周；上/下周切换；点课次查看详情）
  3. 课次编辑（改时间、学员、课程、状态；新增课次；删除课次）
  4. 学员/课程快速选择（编辑课表时下拉选择）
- **响应式**：移动优先（375px 基准），PWA 可选（后续）。

## 七、部署方案（云服务器）

1. 服务器安装：PostgreSQL（建库 `shangkeya` + 账号）、Node.js（≥18）、Nginx。
2. 后端：`backend/` 目录（Express + pg），`systemd` 常驻 + PM2 可选。
3. 前端：桌面工程 `npm run build:web`（新增移动端静态构建）→ 部署到 Nginx 静态目录。
4. 域名 + HTTPS：Nginx + Let's Encrypt（certbot）自动续期。
5. 安全：JWT 短时效 + refresh；密码 bcrypt；API 限流（登录接口）；DB 防火墙仅内网。

## 八、实施阶段（建议顺序）

| 阶段 | 内容 | 产出 | 依赖 |
|---|---|---|---|
| P0 | 数据库 schema + 后端骨架（本地可跑） | `backend/` 项目、建表 SQL、登录/学员/课程/课表 API | 无 |
| P1 | 桌面端数据层改造（本地连后端） | 桌面端在线可用（课件仍本地） | P0 |
| P2 | 手机端课表页面 + 构建 | `/m` 移动页、静态构建 | P0 |
| P3 | 云服务器部署（PG/API/静态/HTTPS） | 公网可用 | P0-P2 + 服务器信息 |
| P4 | 数据迁移（localStorage → 服务器）+ 验证 | 老数据导入脚本 | P3 |

## 九、待确认 / 需用户提供

1. 云服务器：系统（Windows/Linux）、公网 IP / 域名、SSH 或远程桌面访问方式。
2. 服务器是否已安装 PostgreSQL（版本）？未装则部署时一并安装。
3. 后端技术栈是否接受 Node.js + Express（与前端同语言）？
4. 手机端是否需要登录复用现有账号体系（teacher 角色）？
5. 桌面端改造后，旧版本离线使用的本地数据是否仍需保留（兼容/回退）？
